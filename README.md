งานสอบ PEA DevPool 2026 Final Exam
หน้าเว็บทั้งหมดทำด้วย **Next.js** และกติกาการจองทั้งหมดตรวจที่ **Go backend**

## วิธีรัน (3 ขั้น)

**1) เปิดฐานข้อมูล**

```bash
docker compose up -d
```

ไม่มี Docker ก็ได้ ใช้ PostgreSQL ที่ติดตั้งในเครื่อง แล้วสร้าง user/database ชื่อ `tablebook` รหัส `tablebook`
(หรือตั้ง `DATABASE_URL` เป็นของตัวเอง)

**2) รัน Go backend** (terminal ที่ 1)

```bash
cd backend
go run .
```

ครั้งแรกโปรแกรมจะสร้างตาราง (`schema.sql`) และใส่ข้อมูลตัวอย่างให้เอง เห็นข้อความ `API พร้อมใช้งานที่ http://localhost:8080`

**3) รัน Next.js** (terminal ที่ 2)

```bash
cd frontend
npm install
npm run dev
```

เปิด http://localhost:3000

## ฟีเจอร์

**บังคับตามโจทย์**
- สมัคร / เข้าสู่ระบบ / ออกจากระบบ
- สร้างร้าน (ชื่อ รายละเอียด รูปอย่างน้อย 1 รูป จำนวนที่นั่ง เวลาเปิด–ปิด) แก้ไขและลบได้เฉพาะร้านตัวเอง (ตรวจที่ API ตอบ 403)
- จองโต๊ะ ตรวจเวลาเปิดร้าน เวลาที่ผ่านไปแล้ว และที่นั่ง ณ ทุกช่วงเวลา
- หน้า "การจองของฉัน" แก้ไข (ไม่นับที่นั่งเดิมของตัวเองซ้ำ) และยกเลิกตามเวลาที่ร้านกำหนด
- รีวิว 1–5 ดาว (จำนวนเต็ม) + ข้อความ แสดงค่าเฉลี่ยทศนิยมและจำนวนรีวิว รีวิวร้านตัวเองไม่ได้
- เรียง Highest rated! / Most reviewed!

**ต่อยอด**
- ป้าย **Limited Seats Left!** เมื่อที่นั่งเหลือน้อยกว่าเกณฑ์ที่ร้านตั้ง (ค่าเริ่มต้น 20%)
- เจ้าของร้านดูการจองรายวัน พร้อมกราฟที่นั่งทุก 30 นาที
- ตั้งวันหยุดประจำสัปดาห์ และร้านเปิดข้ามเที่ยงคืน
- ค้นหาร้านจากชื่อ ประเภทอาหาร หรือย่าน
- อัปโหลดรูปได้หลายรูป เลือกรูปหลักได้
- กราฟเวลาในหน้าจอง แสดงที่นั่งที่ถูกจองแล้ว + ที่นั่งของเรา + เส้นเต็ม

## API

ทุก endpoint ขึ้นต้นด้วย `/api` ตอบเป็น JSON ถ้าผิดพลาดตอบ `{"error": "ข้อความ"}`

| Method | Path | ต้อง login | หมายเหตุ |
|---|---|---|---|
| POST | `/auth/register` | | 201, 400 ข้อมูลไม่ครบ, 409 อีเมลซ้ำ |
| POST | `/auth/login` | | 200, 401 อีเมลหรือรหัสผ่านผิด |
| POST | `/auth/logout` | | 204 |
| GET | `/auth/me` | ✓ | 200, 401 |
| GET | `/restaurants?sort=rated\|reviews&q=` | | รายการร้าน |
| POST | `/restaurants` | ✓ | 201 สร้างร้าน |
| GET | `/restaurants/{id}` | | รายละเอียด + รีวิว |
| PUT / DELETE | `/restaurants/{id}` | ✓ | 403 ถ้าไม่ใช่เจ้าของ |
| GET | `/restaurants/{id}/availability?date=&exclude=` | | ที่นั่งที่ถูกจองทุก 30 นาที |
| GET | `/restaurants/{id}/bookings?date=` | ✓ | เฉพาะเจ้าของร้าน |
| POST | `/restaurants/{id}/reviews` | ✓ | 201, 403 รีวิวร้านตัวเอง, 400 คะแนนไม่ใช่ 1–5 |
| GET | `/me/restaurants` | ✓ | ร้านของฉัน |
| GET | `/me/bookings` | ✓ | การจองของฉัน |
| POST | `/bookings` | ✓ | 201 / 409 ที่นั่งไม่พอ / 422 นอกเวลาเปิด, เวลาผ่านไปแล้ว, ร้านปิด / 403 จองร้านตัวเอง |
| GET | `/bookings/{id}` | ✓ | เฉพาะของตัวเอง |
| PUT | `/bookings/{id}` | ✓ | กติกาเดียวกับจองใหม่ + 422 ถ้าเลยเวลาแก้ไข |
| DELETE | `/bookings/{id}` | ✓ | ยกเลิก (เปลี่ยนสถานะ ไม่ลบทิ้ง) 204 / 422 เลยเวลา |

**การเลือก status code:** 400 = ข้อมูลรูปแบบผิด, 401 = ยังไม่ login, 403 = login แล้วแต่ไม่มีสิทธิ์,
404 = ไม่พบ (รวมถึงการจองของคนอื่น เพื่อไม่บอกว่ามีอยู่), 409 = ขัดกับสถานะปัจจุบัน (ที่นั่งถูกจองไปแล้ว ลองเวลาอื่นได้),
422 = ข้อมูลถูกรูปแบบแต่ผิดกติกา (นอกเวลาเปิด เวลาผ่านไปแล้ว เลยเวลายกเลิก)

## การออกแบบที่สำคัญ

### 1. ตรวจที่นั่ง "ณ ทุกนาที" (`PeakOccupancy` ใน `rules.go`)

เอาการจองที่ทับช่วงมาบวกกันตรง ๆ ไม่ได้ ตัวอย่างสไลด์ 7: A 7 คน 12:00–12:30, B 7 คน 12:30–13:00 แล้ว C ขอ 3 คน 12:00–13:00
ถ้าบวกตรง ๆ = 17 จะปฏิเสธผิด ทั้งที่ไม่มีช่วงไหนเกิน 10

วิธีที่ใช้คือ **sweep line**: แปลงการจองเป็นเหตุการณ์ "เข้า +คน" และ "ออก −คน" เรียงตามเวลา เดินบวกลบไปเรื่อย ๆ แล้วจำค่าสูงสุด
เวลาเท่ากันให้ "ออก" มาก่อน "เข้า" (A ลุก 12:30 พอดีกับ B มา 12:30 ต้องไม่นับซ้อน) จองได้เมื่อ `ค่าสูงสุด + จำนวนคนใหม่ ≤ ที่นั่ง`

ตอน **แก้ไข** จะไม่ดึงการจองเดิมของตัวเองมานับ (`AND NOT (id = ...)`) จึงไม่นับที่นั่งซ้ำ (สไลด์ 8)

### 2. สองคนจองที่นั่งสุดท้ายพร้อมกัน (`saveBooking` ใน `bookings.go`)

ทั้งการตรวจและการบันทึกอยู่ใน transaction เดียว และเริ่มด้วย `SELECT ... FROM restaurants WHERE id = $1 FOR UPDATE`
คำขอที่สองของร้านเดียวกันต้องรอจนคำขอแรก commit แล้วจึงเห็นการจองของคนแรก → ได้ 409 ไม่มีทางจองเกิน
ร้านต่างกันไม่ต้องรอกัน เพราะล็อกคนละแถว

ทดสอบแล้ว: ร้าน 6 ที่ ส่งคำขอ 6 คนพร้อมกัน 10 คำขอ ได้ 201 หนึ่งครั้ง และ 409 เก้าครั้ง

### 3. เวลาและ timezone

- เก็บเวลาใน DB เป็น `TIMESTAMPTZ` (ภายในเป็น UTC) และแปลงเป็น `Asia/Bangkok` ในโค้ด Go
- `import _ "time/tzdata"` ฝังข้อมูล timezone ไว้ในโปรแกรม ใช้ได้แม้เครื่อง Windows
- "เวลาที่ผ่านไปแล้ว" ตัดสินที่ server (`time.Now()`) ไม่เชื่อนาฬิกาเครื่องผู้ใช้

### 4. ร้านเปิดข้ามเที่ยงคืน 18:00–02:00

เก็บเวลาเปิด–ปิดเป็น "นาทีนับจากเที่ยงคืน" ถ้าเวลาปิด ≤ เวลาเปิด = ปิดวันถัดไป (เวลาปิดจริง = 26:00)
การจองอ้างอิง "วันทำการ" ที่ร้านเปิด เช่น เลือกวันศุกร์ 00:30–01:30 หมายถึงเช้ามืดวันเสาร์ของรอบวันศุกร์
วันหยุดก็ดูจากวันทำการ (`ResolveBooking` / `BusinessDay` พร้อม test)

### 5. เรียงร้านตามคะแนน: 1 รีวิว 5.0 กับ 300 รีวิว 4.8

ใช้ค่าเฉลี่ยถ่วงน้ำหนัก (Bayesian average)

```
score = (ผลรวมคะแนนของร้าน + m × ค่าเฉลี่ยทั้งระบบ) / (จำนวนรีวิว + m)     โดย m = 10
```

ร้านที่รีวิวน้อยจะถูกดึงเข้าหาค่าเฉลี่ยของระบบ ร้าน 4.8 จาก 300 รีวิวจึงอยู่เหนือร้าน 5.0 จาก 1 รีวิว
หน้าจอยังแสดงค่าเฉลี่ยจริง (ทศนิยม 1 ตำแหน่ง) คู่กับจำนวนรีวิว ส่วนร้านที่ยังไม่มีรีวิวอยู่ท้ายสุด

### 6. คำนวณค่าเฉลี่ยตอนอ่าน หรือเก็บไว้

เก็บ `rating_sum` และ `rating_count` ไว้ในตารางร้าน และอัปเดตใน **transaction เดียวกับการบันทึกรีวิว**
หน้า list อ่านเร็วไม่ต้อง `AVG()` ทุกครั้ง ค่าเฉลี่ย = sum / count คำนวณตอนแสดง
เก็บผลรวมแทนค่าเฉลี่ย เพื่อให้ตอนแก้รีวิวอัปเดตได้ถูกต้อง (`sum + ใหม่ − เก่า`) ไม่มีปัญหาปัดเศษสะสม

### 7. Login และการเก็บ session

- Go สร้าง token สุ่ม 32 byte ส่งกลับเป็น cookie `tb_session` แบบ `HttpOnly` + `SameSite=Lax` (+ `Secure` เมื่อใช้ HTTPS)
- DB เก็บเฉพาะ SHA-256 ของ token ถ้า DB หลุดก็เอาไปใช้ login ไม่ได้ อายุ 7 วัน logout = ลบแถวทิ้ง
- Next.js ตั้ง rewrites ให้ `/api/*` และ `/uploads/*` ส่งต่อไป Go → browser เห็นเป็นเว็บเดียวกัน cookie ใช้ได้เลยไม่ต้องตั้ง CORS
- Server Component ส่ง cookie ต่อให้ Go เอง (`lib/server-api.ts`)
- หน้าเว็บแค่ "ซ่อน" สิ่งที่ทำไม่ได้ สิทธิ์จริงตรวจที่ Go ทุกครั้ง

### 8. Server Component กับ Client Component

- **Server Component** (ค่าเริ่มต้น): หน้าที่แค่แสดงข้อมูล เช่น รายการร้าน หน้าการจอง ดึงข้อมูลจาก Go ตอน render ส่ง HTML ที่มีข้อมูลแล้วมาให้ browser
- **Client Component** (`"use client"`): ส่วนที่มี state หรือต้องตอบสนองทันที เช่น ฟอร์มจอง (เปลี่ยนจำนวนคนแล้วกราฟเปลี่ยนทันที) ฟอร์มรีวิว ปุ่มยกเลิก
- หลังบันทึกข้อมูล เรียก `router.refresh()` ให้ Server Component ดึงข้อมูลใหม่

### กติกาเพิ่มเติมที่ตัดสินใจเอง

- เจ้าของร้านจองและรีวิวร้านของตัวเองไม่ได้ (403)
- การแก้ไขการจองมีเส้นตายเดียวกับการยกเลิก
- ยกเลิก = เปลี่ยนสถานะเป็น `cancelled` เก็บประวัติไว้ ที่นั่งคืนทันที
- 1 คน รีวิวร้านหนึ่งได้ 1 ครั้ง ส่งซ้ำเป็นการแก้รีวิวเดิม
- หน้าจอเลือกเวลาทีละ 30 นาที (API รับเวลาใดก็ได้ในรูปแบบ HH:MM)
